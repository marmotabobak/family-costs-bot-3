[![CI/CD](https://github.com/marmotabobak/family-costs-bot-3/workflows/CI%2FCD/badge.svg)](https://github.com/marmotabobak/family-costs-bot-3/actions)

Telegram-бот для учёта семейных расходов с web-панелью управления.

## Функциональность

Система учёта расходов с двумя точками входа: Telegram-бот для ввода расходов и web-панель для управления данными. Оба приложения используют одну PostgreSQL базу данных.

### 📝 Ввод расходов (через бот)

- **Многострочный ввод**: несколько расходов одним сообщением
- **Гибкий формат сумм**: целые и дробные числа с разделителями `.` или `,`
- **Отрицательные суммы**: для корректировок (например, `возврат -500`)
- **Автоматическое сохранение**: при успешном парсинге расходы сохраняются сразу
- **Частичное подтверждение**: если часть строк не распарсилась, бот показывает валидные строки и запрашивает подтверждение перед сохранением
- **Валидация**: ограничение по длине сообщения (4096 символов), строки (100 символов), количеству строк (100)

### 📊 Просмотр расходов (в боте)

- **Меню** `/menu`: интерактивные кнопки для навигации
- **По периодам**: этот месяц, прошлый месяц, другие месяцы (выбор из доступных)
- **По пользователям**: каждый видит расходы всех участников
- **Детальный отчёт**: список расходов по датам, итоговая сумма
- **Форматирование**: разделитель тысяч `_` в боте; дробная часть `.00` не показывается

### 🌐 Web-панель управления

- **Расходы (CRUD)**: пагинированный список, фильтрация (по названию, пользователю, дате, сумме), сортировка по любому полю
- **Массовые операции**: выбор нескольких записей → удаление, смена даты, смена пользователя
- **Добавление и редактирование** отдельных записей
- **Пользователи (CRUD)**: только для admins — добавление, редактирование, удаление
- **Смена пароля**: любой авторизованный пользователь может сменить пароль
- **Авторизация**: вход по паролю, 24-часовая сессия
- **Безопасность**: CSRF-защита на всех формах, rate-limiting на логине (5 попыток / 5 мин)

### 📦 Импорт чеков из ВкусВилл

- Команда `/import` в боте генерирует одноразовую ссылку
- Загрузка JSON-файла с чеком через web-интерфейс
- Просмотр и выбор позиций для сохранения
- Сохранение выбранных позиций в базу данных

### 🔒 Контроль доступа

- **Middleware**: каждое сообщение боту проверяется по таблице `users`; неизвестные пользователи отклоняются
- **Роли**: `admin` (полный доступ) и `user` (расходы — просмотр всех, редактирование только своих)
- **Первый администратор**: задаётся через `ADMIN_TELEGRAM_ID` + `make admin` после запуска сервисов
- **Большие Telegram ID**: поддержка 64-битных идентификаторов (BigInteger в БД)

## Формат сообщения

```
расход сумма
расход сумма
...
```

**Правила:**
- Каждая строка: название расхода + пробел + сумма
- Сумма: целое или вещественное число (разделитель `.` или `,`)
- Сумма может быть отрицательной
- Пустые строки игнорируются
- Максимальная длина сообщения: 4096 символов
- Максимальная длина строки: 100 символов
- Максимальное количество строк: 100

**Примеры:**
```
Продукты 100
вода из Лавки 123.45
морковь 123,00
заказ из Озона №12345 234
возврат -500.24
```

```bash

source venv/bin/activate
```

Подробнее о переменных окружения — в разделе [Конфигурация](#конфигурация) и в [QUICKSTART.md](QUICKSTART.md).

```bash

make admin   # проверяет/создаёт администратора в БД
```

## Конфигурация

| Переменная | Обязательная | Описание |
|------------|-------------|----------|
| `BOT_TOKEN` | ✅ | Токен Telegram-бота |
| `DATABASE_URL` | ✅ | URL PostgreSQL (`postgresql+asyncpg://...`) |
| `ENV` | ❌ | Режим: `dev` / `test` / `prod` (по умолчанию `prod`) |
| `ADMIN_TELEGRAM_ID` | ❌ | Telegram ID первого администратора |
| `ADMIN_DEFAULT_PASSWORD` | ❌ | Пароль по умолчанию для admin при миграции |
| `WEB_BASE_URL` | ❌ | URL web-сервера (для ссылок в боте) |
| `WEB_PASSWORD` | ❌ | Пароль для входа в web-панель |
| `WEB_ROOT_PATH` | ❌ | URL-префикс (nginx → FastAPI, например `/bot`) |

`ENV=dev` — включает SQL-логирование. `ENV=test` — блокирует запуск тестов против prod-БД.

### Первый администратор

Задайте `ADMIN_TELEGRAM_ID` и `ADMIN_DEFAULT_PASSWORD` в `.env` (через `make env`), запустите сервисы (`make up`), затем выполните `make admin` — скрипт проверит наличие пользователя в БД и создаст его при необходимости.

## Особенности реализации

- **Async-first**: aiogram, FastAPI, SQLAlchemy, asyncpg — всё асинхронное
- **Graceful shutdown**: обработчики SIGTERM/SIGINT корректно завершают polling и закрывают пул соединений
- **HTML-экранирование**: весь пользовательский ввод в сообщениях бота экранируется (`html.escape`)
- **Изоляция данных**: `delete_messages_by_ids` фильтрует по `user_id` — пользователь не может удалить чужое
- **64-bit Telegram ID**: поле `user_id` — `BigInteger`, поддерживает ID > 2³²
